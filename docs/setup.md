# Настройка Битрикс24 и авторизация

В этом руководстве описано создание приложения в Битрикс24, способы авторизации портала на сервере и управление токенами.

---

## 1. Создание локального приложения в Битрикс24

Сервер использует официальный OAuth 2.0 протокол Битрикс24. Чтобы получить `client_id` и `client_secret`:

1. В интерфейсе вашего портала Битрикс24 откройте:
   **Разработчикам** (`Developer resources`) → **Другое** (`Other`) → **Локальное приложение** (`Local application`).
2. Выберите тип приложения: **Серверное** (использует только REST API).
3. Заполните URL-адреса обработчиков (замените `https://your-server.example.com` на ваш публичный `APP_URL`):
   - **Путь вашего обработчика (`Handler path`)**:
     ```text
     https://your-server.example.com/oauth/bitrix/callback
     ```
   - **Путь для первоначальной установки (`Initial installation path`)**:
     ```text
     https://your-server.example.com/oauth/bitrix/install
     ```
4. В блоке **Права доступа (`Permissions / Scope`)** отметьте:
   - `CRM (crm)` — обязательно для работы со сделками, лидами, контактами, компаниями и смарт-процессами.
   - `Пользователи (user)` — рекомендуется для инструмента `bitrix_list_users` и верификации профиля.
5. Нажмите **Сохранить** и скопируйте выданные:
   - **Код приложения** → `BITRIX_CLIENT_ID`
   - **Ключ приложения** → `BITRIX_CLIENT_SECRET`

---

## 2. Способы авторизации портала

Сервер поддерживает 3 способа привязки портала Битрикс24:

### Способ А: Автоматически через MCP OAuth 2.1 (рекомендуется)
Подходит для клиентов с поддержкой интерактивного OAuth (Claude Code, Claude Desktop, Codex CLI):
1. Клиент инициирует подключение к `/mcp`.
2. В браузере открывается страница согласия MCP-сервера, а затем форма входа в Битрикс24.
3. После авторизации Битрикс24 возвращает токены на `/oauth/bitrix/callback`. Сервер шифрует их в SQLite и привязывает клиентскую сессию к полученному `connection.id`.

### Способ Б: Через установку в интерфейсе Битрикс24
В настройках созданного локального приложения внутри Битрикс24 нажмите кнопку **Установить** (или **Переустановить**):
- Портал отправит данные на эндпоинт `/oauth/bitrix/install`.
- Сервер проверит приложение через `app.info` и профиль пользователя через `profile.json`, сохранит подключение в базу и подтвердит установку (`BX24.installFinish()`).

### Способ В: Вручную со статическим токеном
Если используется статический токен `MCP_AUTH_TOKEN`, инициируйте OAuth-поток через браузер или cURL:

```bash
curl -i -H "Authorization: Bearer $MCP_AUTH_TOKEN" \
  "https://your-server.example.com/oauth/bitrix/start?domain=your-portal.bitrix24.ru&mode=write_with_confirmation"
```

Перейдите по ссылке из заголовка `Location` в браузере и завершите авторизацию. Сервер вернёт JSON с `connection.id`.

## 3. Управление токенами и безопасность

- **Шифрование AES-256-GCM**: токены доступа и обновления Битрикс24 (`access_token`, `refresh_token`) никогда не сохраняются в открытом виде. Они шифруются симметричным ключом `TOKEN_ENCRYPTION_KEY` перед записью в SQLite.
- **Автоматическое обновление (`TokenManager`)**:
  - Токены Битрикс24 действуют 1 час. Сервер автоматически обновляет их упреждающе (если до истечения осталось менее 60 секунд) или реактивно (при получении ошибки `expired_token` от API).
  - Параллельные запросы к одному порталу дедуплицируются (Singleflight), чтобы не дублировать запросы на обновление.
- **Изоляция подключений (Connection Scoping)**:
  - Токены, выпущенные через MCP OAuth 2.1, привязаны к конкретному профилю Битрикс24. Клиент видит только своё подключение и не может совершать операции от лица других подключений.
  - Статический токен `MCP_AUTH_TOKEN` является административным и позволяет работать с любыми подключениями в БД, явно указывая `connectionId`.
